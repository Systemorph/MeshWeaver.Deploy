Memex Local

This installer puts the memex-local command on this Mac. It stands up the Memex portal on a local Kubernetes (k3s) VM — Colima — and keeps it running across reboots, and it can offer this Mac back to your organisation's fleet as a build host (memex-local backlease enroll).

What is installed, and where

  • /opt/memex/bin/memex-local — the command, on your PATH through /etc/paths.d/memex (open a new terminal window after installing).
  • /opt/memex/share — the Helm chart and the launchd agent templates the command uses.
  • /opt/memex/libexec/vendor — pinned copies of Colima, Lima, kubectl, helm and mkcert. They are used only where this Mac has nothing that meets the minimum version. The installer probes what is already here (Homebrew included) and activates a vendored copy only for a tool that is missing or too old; your own installations are never touched, and nothing is written into Homebrew's folders. memex-local doctor shows, per tool, which copy is in use and why.
  • Optional — Unattended host: a root LaunchDaemon for a headless Mac (a Mac mini leasing itself to the fleet). Not selected by default; it stays unloaded until the managed preference com.memex.local Unattended is true or you load it yourself.

What this package does NOT install — have these before memex-local up

  • Ollama (the local model runtime; ollama on PATH) — from ollama.com or Homebrew. MEMEX_OLLAMA_MODEL=none only skips the large model download; Ollama itself is still required.
  • Docker CLI (docker) and the Azure CLI (az, then az login) — the registry mode pulls the portal image with them. The alternative, building the image from a source checkout, needs the .NET SDK instead.

After installing

memex-local doctor lists every tool, those above included, with where it was found; then memex-local registry <your registry URL> and memex-local up.

Uninstall: memex-local down, then sudo /opt/memex/libexec/uninstall.sh.
